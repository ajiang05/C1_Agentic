# Document chunks: agent handoff

Apply [`202609180003_document_chunks.sql`](../supabase/migrations/202609180003_document_chunks.sql) in the Supabase SQL editor after the first two migrations. This repository migration does not automatically change the hosted database.

The table is `public.document_chunks`:

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, generated by default | Chunk identifier |
| `material_id` | UUID, required | Existing `public.documents.id` for the uploaded material |
| `chapter` | Text, optional | Chapter number or title, such as `Chapter 4 — Graphs` |
| `content` | Text, required | Nonempty chunk text |
| `embedding` | pgvector `vector`, optional | Numeric embedding; can be filled after text ingestion |

Create the profile, course, and document before inserting its chunks. There is no separate `materials` table in the current schema: `material_id` is the agent-facing name for a document ID.

## Example insert

Using your agent's existing Supabase client on the backend:

```js
const { data, error } = await supabase
  .from('document_chunks')
  .insert({
    material_id: documentId,
    chapter: 'Chapter 4 — Graphs',
    content: chunkText,
    embedding: JSON.stringify(embeddingValues), // Numeric array -> '[0.1,...]'
  })
  .select('id, material_id, chapter, content')
  .single();

if (error) throw error;
```

Inserts and embedding updates require a trusted backend client. Authenticated students can read only chunks belonging to their documents. Unauthenticated access is disabled. The service-role client bypasses RLS, so backend retrieval must scope queries to documents belonging to the verified student.

## Embedding model agreement

The model and vector size have not been specified, so the migration uses unrestricted `vector`, not a guessed dimension. Use the same model and dimension for stored embeddings and query embeddings. Once the team agrees on a size, a later migration can constrain the column to `vector(N)` and add an appropriate similarity index. This migration adds a material lookup index only; it does not implement a vector-search RPC or generate embeddings.

Supabase supports embeddings through the [pgvector extension](https://supabase.com/docs/guides/database/extensions/pgvector). The extension supports [vectors without a fixed column dimension](https://github.com/pgvector/pgvector#can-i-store-vectors-with-different-dimensions-in-the-same-column), but comparisons require compatible dimensions and similarity indexing requires a fixed-size expression or column.

## Relationship to source passages

`source_passages` remains the citation layer used by `concept_sources` and `content_sources`. `document_chunks` is the agent's retrieval layer. Neither table automatically populates the other, and their IDs are not interchangeable. Ingestion must still create source passages and citation links for lessons and concepts; inserting only chunks does not make a concept source-backed in the learning-memory snapshot.
